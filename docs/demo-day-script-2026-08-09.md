> 公网地址：https://kentucky-until-encouraged-ministers.trycloudflare.com
> 用法：**【做】= 鼠标操作；【说】= 照着念；【看】= 确认画面**

---

## 0:00-0:15 开场 + Landing

【做】打开公网 URL（无痕窗口已预热，本页已打开）

【说】
> "大家好，这是 PrismSettle——AI Agent 世界的担保交易。
> 一句话：Agent 之间雇佣干活，钱不直接给，锁进智能合约，干完自动放款。
> 下面 3 分钟，看一个真实案例：AI 审计 Agent 接单、交付、打回、仲裁、结算——每一笔都是 Monad 测试网上的真实交易。"

【看】Landing 页三张卡片（P2P / P2A / A2A）出现

---

## 0:15-0:30 切到 Jobs 页

【做】点导航栏 Jobs

【说】
> "屏幕上这些不是演示数据，是测试网上真实跑过的任务——13 个任务，9 个已经完成结算。我们点开一个，看完整过程。"

【看】任务列表出现（数字：13 个 / 9 完成）

---

## 0:30-1:15 历史回放（45 秒 · 完整仲裁故事）

【做】点任意已完成任务 → 详情页自动加载演示回放 → 跟着节奏滚聊天记录

【说 1 · 抢单竞争屏】
> "任务一发布，三个审计 Agent 同时竞争抢单：一个资格不符，一个慢了一步，senior 胜出。谁赢谁输、为什么——链上全都查得到。"

【说 2 · 交付屏】（顺手点开交付物全文）
> "胜出的 Agent 提交了完整审计报告，全文在这，哈希同时锚定上链。内容有没有被篡改，前端一键校验。"

【说 3 · 打回屏】
> "买家对交付不满意，用自然语言打回两次，每次都有具体修改意见。"

【说 4 · 仲裁屏】
> "provider 不服，提起仲裁。注意：仲裁双方都要押金，败方的押金没收给仲裁方。独立仲裁方逐条核对后，裁定 provider 胜。"

【说 5 · 结算屏】
> "公告期过后自动结算，托管资金全额放款。每一个气泡背后，都是一笔真实链上交易——地址在 README，评审可以随时验证。"

【看】完整聊天流 + 交付物全文 + 校验绿盾

---

## 1:15-2:30 现场跑 direct 场景（75 秒 · 压轴）

【做】回 Jobs → 新建任务 → Demo 面板保持默认（智能合约安全审计 / 5 USDC / Senior Auditor）→ 场景选「✅ 直接完成」→ 点开始

【说 1 · 刚点开始时】
> "光看回放不够，现在现场跑一场新的。我全程不碰键盘——看，三个 Agent 自己开始抢单了。"

【说 2 · 抢单/交付进行中】（等聊天出现 2-3 条后）
> "注意顶部状态条：Created、Funded、Assigned、Submitted——每一步都实时推进。这段对话是 LLM 实时生成的，不是录好的。"

【说 3 · 结算 🎉 出现时】
> "买家直接验收通过，托管资金自动结算给 provider——信任靠合约，不靠承诺。"

【看】聊天逐条生成 + 状态条推进 + 结算消息

## 应急台词（卡住时照念）

| 情况 | 台词 |
|------|------|
| 交易在等确认（RPC 慢） | "这笔交易正在等链上确认，Monad 测试网偶尔会慢，我们等几秒。" |
| 回放打不开 | 直接换任务："这个任务看不了，我们换一个——数据都在链上，不影响。" |
| 现场 demo 起不来 | "后端服务需要重启一下，我们用刚才的回放继续讲。" |
| 时间快超了 | "时间关系，仲裁的完整过程大家刚才在回放里已经看过了。" |
| 评审问：仲裁赢了为什么不加分 | "仲裁只解决钱归谁，不影响声誉分——防止有人靠打官司刷声誉。" |
| 评审问：和中心化平台区别 | "托管、放款、仲裁全部链上可审计，没有平台作恶的空间。" |
